Index Compare

Multi-query two indices side by side: settings, results and ranking info
Connection
Key requirements: the API key needs the search ACL (multi-query with getRankingInfo) and the settings ACL (to read both indices' settings, synonyms and rules). A plain search-only key will fail those loads. Prefer a scoped key limited to these two indices over an Admin key. The key is kept in memory only and never saved.
Shared search params & display i Search params (sent identically to both indices):
  • filters: an Algolia filter expression, e.g. brand:"Acme" AND price < 50.
  • hitsPerPage: how many results each side returns. This is also the depth used for overlap and rank-shift metrics.
  • Extra params (JSON): any other search parameter merged into both requests, e.g. ruleContexts, optionalFilters, aroundLatLng.
Display (only changes how hits look, no new query):
  • Title / Image attribute: which record attribute is shown as the hit title and thumbnail. Leave empty to auto-detect (title, name, image…).
  • Extra attributes: comma-separated attributes shown under each hit. Dot paths like price.value work.
Applies to the Results and Batch tabs.
Always sent: getRankingInfo: true, analytics: false, clickAnalytics: false (keeps dev testing out of analytics).
